# 身份与权限的边界

认证成功回答的是**这是谁**，不回答**他能做什么**，并且永远不会回答。这一页把线画出来，
并写清围绕它的那五个问题各自由谁来答。

## 五个问题，不是一个

| | 回答什么 | 归谁 |
|---|---|---|
| **身份** | 这是哪一个主体？ | SoulAuth |
| **认证** | 这个身份是否已按要求的强度、在刚才被证明？ | SoulAuth |
| **权能** | 这个主体凭什么在该领域内具备做这类事的资格？ | 你的应用 |
| **授权判定** | **这一次具体请求**是否允许？ | 你的应用 |
| **效果** | 现实是否真的改变，最终结果是什么？ | 你的应用 |

五者彼此相关，但不能相互替代。SoulAuth 回答前两个，到此为止。

典型的失败是把前一个问题的答案当作后一个问题的答案：*令牌验过了，所以这个操作被允许*。
这条推断从不成立。

## 权能属于领域，不属于主体

权能不是主体随身携带的属性，它**存在于某个领域之内**，同一个主体在不同领域中
持有的权能各不相同。

一个能管理计费系统的主体，在部署流水线里没有任何资格，除非流水线本身授予了它。
它在两者之间移动时，身份没有发生任何变化，变的只是提问的领域。

正因如此，SoulAuth 自己的 RBAC **只治理 SoulAuth 的控制平面**：谁可以注册 OIDC
客户端，谁可以读审计日志。它不是给你的业务用的权限服务：SoulAuth 不知道你的业务
有哪些资源，也不知道它们的规则。

## 认证能做什么，不能做什么

认证条件可以**约束**授权判定，但不能**创造**权能。

对敏感操作要求 MFA 是正当的约束，它收窄了一项既有权能的行使条件。但无论认证强度
多高，都不会凭空给出主体本来没有的权能。`acr` 与 `amr` 描述的是「他如何完成了认证」，
不是「他可以做什么」。

反过来同样成立：一项权能确实存在，也可能因为背后的认证太弱或太旧而不可行使。

## 认证过，不等于此刻仍然合格

一枚有效令牌证明的是「认证曾经发生」，而不是「该主体此刻仍然合格」。

从签发到使用之间，这个主体可能已被停用、被移除某个角色，或者目标资源已移出它的
范围。任何把「令牌仍然有效」当作「权限依然成立」的做法，都是把一次过去的事件
当成了当下的状态。

落到实践上：在操作发生的那一刻检查权能，而不是在登录的那一刻。

::: warning 这里的「此刻」有多准
吊销在 `AUTH_SESSION_CACHE_TTL_SECONDS` 之内到达其它副本。
因此在身份被停用之后的短时间内，令牌仍可能被接受。默认 5 秒，窗口很小但不是零。
单实例部署根本没有这个窗口：处理吊销的那个实例就是唯一在服务流量的实例。
:::

## 连续性不冻结任何东西

身份跨时间保持不变，是身份自身的性质，不是对权能的承诺。

`Agent-17` 可以多年都是同一个主体，与此同时它的权限被撤销、范围被收窄、
对某个领域的访问被完全收回。稳定的身份让这些变更**可归因**，而不是让它们不可能发生。

## Claims 与令牌只在各自的契约内有效

**Claims** 描述的是认证事件与 subject 本身：`sub`、`iss`、`auth_time`、`sid`，
以及 scope 允许的档案字段。其中没有一项是授权陈述。一个把 `email_verified` 读成
「可以访问计费」的客户端，是在自行发明签发方从未做出的规则。

**访问令牌**证明的是：某个客户端**在资源所有者授权下、在所示 scope 范围内**获得了
许可。OAuth 的 scope 是一条委托边界，划定客户端代表他人**最多可以尝试**什么。
它不是授予用户的权能，也不是关于你的应用应当允许什么的陈述。

一个叫 `admin` 的 scope 不授予任何东西。它的含义只是：用户同意这个客户端可以去问。

## 有权能，不等于操作可执行

即便权能成立，操作仍可能正当地失败：

- 领域前置条件不满足（账号已关闭、资源被锁定）；
- 并发变更让这次操作失去意义；
- 效果在下游被拒绝。

反过来也一样：前置条件失败并不意味着该主体缺乏权能。把两者分开，错误信息才可能
如实：「你无权这样做」与「这件事现在做不了」是两句不同的话，说错一句，
用户就会去修错误的地方。

同理，授权判定不等于效果。「允许」的意思是这次尝试可以继续；现实是否改变是另一个
事实，而只有效果才配出现在「发生了什么」的陈述里。

## 委托不替换身份

一个主体代表另一个主体行动时，两者都留在记录中。委托调整的是权能与归因，
不覆盖「是谁在行动」。

一条审计记录若在有委托的情况下只写「账号所有者做的」，就毁掉了这条记录存在的
唯一理由。

## AI 主体

上述一切原样适用。有一条要单独说，因为非人主体这条路上最容易走近路：

**长期的身份不等于长期的权能。** AI 主体的身份之所以持久，恰恰是为了让它的权能
能够被调整、收窄和撤销，而归因依然成立。持久身份的意义在于让撤销变得有意义，
不是为了免于撤销。

## Soulseed 边界

在 Soulseed 部署中，认证一个主体不授予它在那一侧的任何治理地位。SoulAuth 持有的是
指向 canonical actor 的引用，但既不能定义它，也不能修改它。
