# 审计

## 记录的内容

认证事件——登录成功与失败、OAuth 登录、登出、口令重置、MFA 失败、权限拒绝、
限流违规、账号上锁与解锁。

写入方遵守两条规则：

- **绝不阻塞请求。** `record` 把事件投进队列就返回；由专用的写入任务消费，
  遇到数据库瞬时故障会重试，进程关闭时先把队列排空。用户的操作不会等审计落库，
  正常重启也不会让排队中的事件消失。
- **绝不记录凭据。** 只记 action、分类、状态、IP、User-Agent 和少量非敏感上下文。
- **可验篡改。** 每一行按哈希链到上一行，链头每小时用一把不在数据库里的私钥
  签一次。`GET /api/audit/integrity` 会重新推导整条链并验证 checkpoint，
  链有断点时指出第一处。
  <Status kind="tested" guard="conformance::f4" />

升级到带链的版本之前写下的行没有自己的链。报告把它们单独计为 `unchained`，
不当作断链：升级不该反过来指控你已有的历史被篡改过。受保护的是从那时起写入的行。
