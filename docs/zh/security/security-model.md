# 安全模型

SoulAuth 保护什么、怎么保护，以及责任到哪里为止。

## 保护范围

保护范围只有三项，此外没有：

1. **静态凭证**：把数据库读走的人，没法凭它以任何人的身份认证。
2. **认证判定**：一个身份主张不能被伪造、重放或提权。
3. **归因**：谁在何时、以何种方式完成了认证的记录。

应用自身的授权不在这个范围内。认证成功陈述的是「是谁」，不授予任何权限。
[身份与权限的边界](/zh/spec/identity-vs-authority)

## 静态凭证的保护

| 秘密 | 怎么存 |
|---|---|
| 口令 | Argon2 |
| MFA 备用码 | Argon2，逐条校验 |
| TOTP 密钥 | ChaCha20-Poly1305，必须可逆，因为算验证码要用它 |
| 客户端密钥 | Argon2 |
| PKCE verifier | SHA-256，常数时间比较 |
| 会话令牌 | SHA-256 指纹 |
| OIDC 访问与刷新令牌 | SHA-256 指纹 |
| 授权码 | SHA-256 指纹 |
| 口令重置令牌 | SHA-256 指纹 |
| 邮箱验证令牌 | SHA-256 指纹 |

而且哈希函数是真哈希而不是某种编码。

### 密钥本身住在哪

上面那张表说的是数据库里存什么。有四把密钥**刻意不在**其中，因为它们正是用来
校验数据库内容的那一方：

| 密钥 | 作用 | 住在哪 |
|---|---|---|
| `JWT_SECRET` | 签会话令牌 | 进程环境变量 |
| OIDC 签名密钥 | 签 ID Token | 文件，或进程环境变量 |
| `MFA_SECRET_ENCRYPTION_KEY` | 加密存下来的 TOTP 密钥 | 进程环境变量 |
| `AUDIT_INTEGRITY_KEY` | 签审计 checkpoint | 进程环境变量 |

把审计密钥放在数据库之外，正是 checkpoint 有意义的前提：够得着数据库的攻击者
可以改行、可以把哈希链整段重算，但签不出对得上的签名。够得着进程环境的攻击者
可以。这就是这四把钥匙所在的那条边界，也是生产清单把它们当作独立的备份材料、
而不是数据库转储的一部分来对待的原因。

### 为什么用两种不同算法

口令熵低且由人选定，因此让离线爆破变贵的只能是慢哈希，也就是 Argon2。

Bearer 令牌是 32 字节随机值或已签名 JWT。没有什么可猜的，而且它们在**每一个已认证
请求**上都要被查一次。慢哈希在这里换不到额外的安全，只会让每个请求都多花几十毫秒。
所以口令用 Argon2，令牌用 SHA-256：两者要防的攻击不同。

### 会话那一条值得单说

`session.token` 曾经保存的是完整签名 JWT，与客户端手中那一枚逐字节相同：
读到那张表就等于拿到了系统里所有在线会话的令牌。现在存的是指纹，吊销查询照样能做。

## 认证判定的保护

**口令。** Argon2，并在启动时算好一个哑哈希，使得对不存在账号的登录与对真实账号的
登录耗时相同。

**MFA。** TOTP，并按用户持久化一个重放水位线，因此同一个验证码不能被重用，
跨副本也不行。

**锁定与限流。** 按账号与按 IP 两个维度，都存在数据库里，因此跨副本共享。

**AI 主体。** 对服务端签发的一次性挑战做 Ed25519 签名。带域分隔、绑定 issuer，
所以一枚签名既不能被重放到别的用途，也不能被重放到别的部署。挑战在验签**之前**
被消费，关掉了并发使用的窗口。[AI 原生身份](/zh/concepts/ai-native-identity)

**OIDC。** 授权码流程 + PKCE —— public 客户端强制、confidential 客户端默认开启，
只收 `S256`。刷新令牌轮换；复用一枚已消费的
令牌被当作泄露处理，吊销整个令牌族。

## 设计上不会越过的边界

**服务无法改自己的表结构。** SoulAuth 不发任何 DDL；两个 SQL 文件由运维导入。
一个能改写自己表结构的认证服务，也能改写自己的约束。

**错误不泄露内部。** 数据库与服务器错误统一收敛成一个 `internal_error` 码。
账号不存在与口令错误不可区分。引导端点对「令牌错误」与「已初始化」返回同一状态码，
因此失效令牌无法用来探测部署状态。

**对 Agent 只持公钥。** SoulAuth 从不持有 Agent 的私钥。与口令哈希不同，
存着的那个值连离线攻击的目标都算不上。
